# Глоссарий

[English](../en/glossary.md)

Глоссарий — данные FAS. Пакет в git — это `configs/concepts/`, `configs/glossary/` и `configs/metrics/`. Релиз — неизменяемая копия этого документа в object store. Загрузка книги запоминает id релиза, с которым она собрана.

`borrowings_lt`, `borrowings_st` и `lease_liability` — строки запаса, из которых считается `total_debt`. Сам `total_debt` — метрика в `configs/metrics/coverage.yaml`, а не понятие строки. Подписи «Заемные средства» и «Займы и кредиты» неоднозначны: их разбирают код строки, заголовок раздела или лист модели долга.

`GLOSSARY_AUTO_PROMOTE` по умолчанию выключен. Метка, выученная на книгах, сама активным релизом не становится. `uv run fas glossary shadow <version>` строит shadow-отчёт кандидата. Пороги и canary-гейт — в [design-v0.23.md](../design-v0.23.md) §5.9, не на этой странице.

Размеченные книги и команда `fas eval mapping` описаны в [eval/README.md](../../eval/README.md).

## Чтение и запись

`GET /v1/glossary` возвращает голову и `ETag` вида `h-{seq}`. Без опубликованной головы — `404`, запись не делается.

`POST /v1/glossary/bootstrap` публикует git-пакет как релиз 1, если головы ещё нет. Повторный вызов возвращает текущую голову. Если задан `FAS_ADMIN_TOKEN`, нужен `X-Admin-Token`. В CLI то же делает `uv run fas glossary bootstrap`. Cron (`glossary_mine`, `cluster_unmapped`) и `fas eval` / `fas learn` требуют уже существующую голову и сами не публикуют.

Эти чтения только читают. Без головы — `404`, `_publish_git` не вызывается:

- `GET /v1/glossary`
- `GET /v1/glossary/releases`
- `GET /v1/glossary/releases/{version}`
- `GET /v1/glossary/content`
- `GET /v1/glossary/concepts`
- `GET /v1/glossary/diff`
- `GET /v1/glossary/events`

Эти тоже не публикуют:

- `GET /v1/glossary/labels?q=`
- `GET /v1/glossary/impact` — **устарел**; всегда `501 not_implemented`. Контракт в design — `GET /v1/glossary/releases/{version}/impact` (ещё не реализован). Пустой `{"books": []}` больше не отдаётся.
- `GET /v1/glossary/stats?from=&to=&profile_id=`
- `GET /v1/glossary/proposals` и `GET /v1/glossary/proposals/{proposal_id}`
- `POST /v1/glossary:resolve`

Запись:

- `POST /v1/glossary/bootstrap` — первый релиз из git (идемпотентно).
- `POST /v1/glossary/releases` — релиз из `ops` или замена документа при `mode=replace`. Нужна голова (`404` до bootstrap).
- `POST /v1/glossary/transitions` — перевод релиза в другой статус. Запрос ставит операцию `glossary.validate` в очередь `fas:glossary`, воркер выполняет теневую проверку и запись. Успешный переход запускает пересчёт книг.
- `POST /v1/glossary:rollback` — включает предыдущий релиз и запускает ремап.
- `POST /v1/glossary/proposals` и `POST /v1/glossary/proposals:decide` — открыть предложение или пакетом принять и отклонить.

Если задан `FAS_ADMIN_TOKEN`, bootstrap, релизы, переходы, откат, решения по предложениям и `PUT /v1/profiles/{profile}` требуют заголовок `X-Admin-Token` (проверка до идемпотентного replay). Пустое значение токен не проверяет. В проде задавайте `FAS_REQUIRE_ADMIN_TOKEN=true`, чтобы старт без токена падал (fail-closed); см. [настройки — периметр auth](settings.md#периметр-auth-prod). `X-User-Id` по-прежнему не аутентификация.

## Resolve

`POST /v1/glossary:resolve` сопоставляет одну метку с понятием. Тело — объект. Передаётся `label` или `text`, либо `path_text`: меткой становится последний сегмент после ` › `. Вместе `label` и `path_text` дают `400`. Необязательные поля — `unit`, `profile_id`, `version`.

Вызов ничего не пишет. `version`, которой нет в хранилище, — это `404`, и git-пакет не публикуется. Без опубликованной головы ответ берётся из git-документа, а `state` равен null.

Лексическое попадание, не прошедшее проверку единицы, остаётся в `candidates` с `structure_pass: false` и `match` null. Модель не вызывается. Метка без лексического попадания ранжируется только если настроен сервер embed или rerank, и этот ранж не тратит бюджет choice-модели на книгу.

## Оси понятия

Запись в `configs/concepts/core.yaml` разделяет роль (`semantic_role`: measure, assumption, parameter), размерность (`dimension`, каталог `configs/dimensions.yaml`), временную природу (`temporal_nature`: stock, flow, rate, point_in_time) и знак (`expected_sign`: только inflow или outflow). Роль написана у понятия. То, что ячейка — ввод, её не выбирает. `energy_tariff` — договорный parameter с основой `energy`. `forecast_energy_tariff` — другая сущность: assumption, размерность `currency_per_energy`, временная природа `rate`, основа `energy`. Свёртка по времени — `none`. Совпадение физических показателей не делает их одним понятием. Метки отличимые: «прогнозный тариф», «ожидаемая цена реализации», «прогнозная цена электроэнергии»; по-английски — `Merchant price forecast`, `Electricity price forecast`, `Merchant price (real)`, `Merchant price (nominal)`. Сравнение снимает хвост в скобках, но обе поверхности хранятся: строка получает ту, которая совпала. Общие синонимы с `energy_tariff` без дополнительного контекста не делятся. Метка без пометки `ambiguous: true` у обоих понятий в каталог не входит. Помеченная так метка не выбирает одно понятие: у строки статус `ambiguous` и несколько кандидатов. Резолв отдаёт этих кандидатов и не считает метку отсутствующей. Понятие введено решением 43; решение 42 зафиксировало оси и не вводило этот id. Основа `real` или `nominal` пишется на привязке (`price_terms`), не новым понятием. Скобки — `(real)`, `(real terms)`, `(nominal)`, `(nominal terms)`. Строки с разной основой не становятся ничьей и не дают две основные строки одного понятия: обе остаются связанными, ни одна не основная. Общая метка кейса (`Mid case`, `Low case`, `Applied`) сама понятия не выбирает. Если ближайший заголовок раздела даёт ровно одно понятие, строка привязывается к нему, и в доказательствах стоит `section_heading`. Метка, которая уже разобрана, заголовком не переписывается. Это решение 44. Договорная и PPA-цена остаётся `energy_tariff` или без привязки. `capacity_tariff` — плата за мощность с расчётным периодом `billing_period`, это не период отчёта и не цена энергии. Совпадение физических показателей не доказывает экономическую совместимость. Свёртка по времени следует из временной природы, если нет явного `aggregation`: ставка не усредняется. Свёртка по объектам — только явный `weighted_average` с понятием-весом. Вес обязателен, и его размерность согласована с усредняемым: ставка — с деньгами, энергией, мощностью, числом, площадью или сроком; тариф энергии — только с энергией; тариф мощности — только с мощностью. В каталоге это ни у кого не включено. Конкретная валюта, МВт·ч и масштаб в понятие не входят: они остаются у строки и факта книги.

Прежние `kind` и `unit` по-прежнему читаются. `kind: ratio` — мера безразмерной размерности. `expected_sign: stock` — запас без знака. Загрузчик отдаёт старые `kind` и `unit` как алиасы, поэтому уже записанные привязки и типы моделей их понимают.

## Связи понятий

Реестр типов — `finance_analysis.domain.relations`. Рёбра по-прежнему лежат на понятии в `configs/concepts/`, отдельный граф связей не заводится. Обратное ребро в данные не дописывается. У `cfads` связь `related_to` указывает на `dscr` и обратно не выводится. `energy_tariff` и `forecast_energy_tariff` связаны двумя явными рёбрами. `narrower_than` из `broader_than` не создаётся.

Смысловая связь не подставляет одно понятие вместо другого и не складывает цели в метрику. Расчёт спрашивает реестр. Подстановка и агрегация сейчас ни одному типу не даны. Сверка разрешена только `composed_of`: этот список совпадает с `configs/identities/` и питает голос `lf.identity`. Сумма частей во вход метрики не идёт. `related_to` в сверку, подстановку и агрегацию не входит.

`calculated_from` — зависимость формулы, не список частей и не право считать по связи. `derived_from` — смысловое происхождение, без арифметики. Оба типа активны в схеме и в каталоге пока не заполнены. `equivalent_to`, `supersedes` и `replaced_by` неактивны: пакет с ними не собирается. Начисленные проценты `interest` и уплаченные `interest_paid` эквивалентными не считаются.

| Тип | Статус | Направление | Транзитивно | Обратное | Обратное обязательно | Циклы | Подстановка | Агрегация | Сверка | Концы |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| `composed_of` | активен | прямое | нет | нет | нет | нет | нет | нет | да | measure → measure, одна размерность |
| `calculated_from` | активен | прямое | нет | нет | нет | нет | нет | нет | нет | понятие → понятие |
| `derived_from` | активен | прямое | нет | нет | нет | нет | нет | нет | нет | понятие → понятие |
| `broader_than` | активен | прямое | да | `narrower_than` | нет | нет | нет | нет | нет | понятие → понятие |
| `narrower_than` | активен | прямое | да | `broader_than` | нет | нет | нет | нет | нет | понятие → понятие |
| `related_to` | активен | симметричное | нет | само | нет | да | нет | нет | нет | понятие → понятие |
| `equivalent_to` | зарезервирован | симметричное | да | само | нет | да | нет | нет | нет | понятие → понятие |
| `supersedes` | зарезервирован | прямое | нет | `replaced_by` | нет | нет | нет | нет | нет | понятие → понятие |

| `contradicts` | активен | симметричное | нет | само | нет | да | нет | нет | нет | понятие → понятие |
| `requires` | активен | прямое | нет | нет | нет | нет | нет | нет | нет | понятие → понятие |

Транзитивность в таблице — свойство типа. Замыкание при загрузке не строится. Иерархия `broader_than` / `narrower_than` и опубликованное поле `broader` по-прежнему один граф от родителя к ребёнку: цикл этого графа пакет отвергает. Неизвестный тип, неактивный тип, чужая роль или размерность, ребро на отсутствующее понятие, запрещённый цикл и пара типа с его обратным типом в одну сторону дают ошибку загрузки на русском.
